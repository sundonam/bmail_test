System architecture
Stakeholder roles and interactions — based on Figure 3, Lee et al. (2025)
bMail User
  • Registers bMail ID at ISP (real name or anonymous)
  • Selects bCA and grants identity permission
  • Provides backup verification channels
  • Approves or rejects identification requests
  • Registers on platforms using bMail ID
  • Initiates ID-change protocol when needed
bMail ISP
  • Issues bMail domain names (bgmail.com etc.)
  • Enforces authentication (DKIM/SPF/DMARC/ARC)
  • Lists certified domains on public portal
  • Manages identification service (with user approval)
  • Routes verification via backup channels
  • Issues signed ID-change tokens to platforms
  • Monitors propagation and blocks fake domains
  • Never stores personal data (zero-copy)
bCA (Certification Authority)
  • Holds genuine identity data (telco, bank, govt)
  • Issues signed certificate tokens to ISP
  • Personal data never transmitted to ISP
  • Certifies pseudonyms and real names alike
  • Verifies identity for ID-change requests
  • Annual certificate renewal
bMember Platform
  • Recognises bMembers as identifiable customers
  • Implements secure ID-change protocol with ISP
  • Tags reviews by author certification status
  • Reduces fake reviews and fake accounts
  • Retains customers through lifelong bMail IDs
  • Gains social responsibility reputation
